# Описание текущей реализации цепи Маркова

## 1. Общее назначение

Система реализует **адаптивную цепь Маркова** для прогнозирования риска инцидентов производительности на основе временных рядов метрик (корреляция «скорость–ожидания», тренды). Модель обучается в реальном времени на минутных переходах между дискретными состояниями, применяет **забывание** для учёта старения данных, строит **поглощающую матрицу** (критические состояния становятся поглощающими) и вычисляет **вероятность попадания в критическое множество** на заданном горизонте.

Дополнительно реализован **модуль профилирования нагрузки**, который строит эталонные профили (оперативный, суточный, недельный), сравнивает текущий профиль с эталоном, вычисляет JS-дивергенцию и логирует аномалии.

## 2. Таблицы базы данных

### 2.1. Основные таблицы цепи Маркова

| Таблица | Назначение |
|---------|------------|
| `markov_config` | Параметры обучения, забывания, горизонт прогноза, пороги, флаги адаптивности, время последнего инцидента. |
| `state_descriptions` | Справочник всех 189 состояний (correlation, os_trend, wait_trend). Заполняется функцией `fill_state_descriptions()`. |
| `markov_chain` | Текущее и предыдущее состояние системы (всегда одна строка). Используется для пошагового обучения. |
| `transition_log` | Журнал всех переходов между состояниями с временными метками. Основа для анализа и проверки достаточности обучения. |
| `markov_frequencies` | Накопление сырых частот переходов (обновляются каждую минуту; могут быть дробными после забывания). |
| `markov_probabilities` | Матрица вероятностей переходов, пересчитываемая из частот. |
| `markov_absorbing` | Поглощающая матрица для многошагового прогноза (критические состояния – поглощающие). |
| `critical_states` | Динамический список аварийных состояний (поглощающих). Обновляется эмпирически через `refresh_critical_states()`. |
| `prediction_log` | Журнал прогнозов: время, предсказанный риск, фактический исход (заполняется позже), горизонт, текущее состояние. |
| `mchain_quality_metrics_history` | Агрегированные суточные метрики качества прогнозов (Brier, ECE, MCE, ROC‑AUC и др.). |
| `apply_forgetting_log` | Лог вызовов функции забывания (применённый alpha, детали расчёта). |
| `mchain_error_log` | Журнал ошибок, возникающих при работе функций. |
| `mchain_quality_errors` | Ошибки, связанные с прогнозированием. |
| `mchain_train_progress_log` | Лог прогресса при историческом обучении. |
| `forgetting_optimization_log` | Результаты экспериментов по подбору параметров забывания. |

### 2.2. Таблицы профилирования нагрузки

| Таблица | Назначение |
|---------|------------|
| `performance_history` | История метрик производительности (операционная скорость, ожидания, корреляция, углы трендов) с минутной детализацией. |
| `profile_aggregated` | Агрегированные профили: оперативный (60 мин), суточный (24 ч), недельный (7 дн). Содержат гистограмму состояний, среднюю корреляцию, долю критических, энтропию, углы, долю петель и т.д. |
| `profile_baseline` | Эталонные профили для каждого часа и дня недели, построенные на безынцидентных периодах. Хранят средние и стандартные отклонения метрик. |
| `anomaly_log` | Журнал обнаруженных аномалий профилей (Z-оценки метрик, превысившие порог). |
| `incident_free_window_current` | Хранит последнее найденное безынцидентное окно (одна строка). |
| `profile_comparison_log` | Журнал сравнений эталонного и текущего профилей: статус (NORMAL/WARNING/CRITICAL), JS-дивергенция, максимальный предсказанный риск, флаг предаварийного состояния. |

## 3. Основные функции цепи Маркова

### 3.1. Обучение и управление состоянием

| Функция | Описание |
|---------|----------|
| `mchain_train_step()` | Основной шаг обучения (вызов каждую минуту): получает текущие метрики, определяет состояние, логирует переход, обновляет цепь, вызывает плановое забывание и формирует прогноз. |
| `mchain_log_transition(from, to)` | Логирует переход в `transition_log` и обновляет частоты в `markov_frequencies`. |
| `mchain_get_current_state_id()` | Возвращает идентификатор текущего состояния (для отладки). |
| `get_state_id(r, os_trend, wait_trend)` | Вычисляет идентификатор состояния по трём параметрам. |
| `decode_state_id(state_id)` | Обратное преобразование – возвращает параметры состояния по его ID. |
| `fill_state_descriptions()` | Заполняет справочник `state_descriptions` всеми 189 комбинациями. |

### 3.2. Забывание и управление вероятностями

| Функция | Описание |
|---------|----------|
| `mchain_apply_forgetting(alpha_override, max_alpha)` | Применяет забывание: умножает все частоты на (1‑alpha), удаляет малые значения, пересчитывает вероятности и перестраивает поглощающую матрицу. Может использовать адаптивный alpha (зависит от времени с последнего инцидента). |
| `update_markov_probabilities()` | Пересчитывает вероятности из частот (нормировка по строкам). |
| `rebuild_markov_absorbing()` | Строит поглощающую матрицу: критические состояния становятся поглощающими (вероятность остаться = 1). |
| `mchain_check_sufficiency()` | Проверяет, достаточно ли накоплено данных (число переходов >= порога), возвращает коэффициент стабильности. |
| `mchain_enable_forgetting_when_sufficient()` | Включает адаптивное забывание только если `mchain_check_sufficiency()` вернула TRUE. |
| `mchain_force_enable_forgetting()` | Принудительно включает адаптивное забывание. |
| `refresh_stability_threshold()` | Адаптивно настраивает `min_freq_for_stability` на основе числа переходов за 14 дней. |

### 3.3. Прогнозирование риска

| Функция | Описание |
|---------|----------|
| `mchain_predict_risk_k_v2(state_id, k)` | Вычисляет вероятность хотя бы одного попадания в критическое множество за k шагов (минут) с использованием итеративного умножения вектора. |
| `mchain_predict_risk_current_horizon()` | Прогноз риска на горизонт, заданный в `markov_config.forecast_horizon_minutes`. |
| `collect_prediction(p_time)` | Формирует прогноз для заданного времени и сохраняет в `prediction_log`. |
| `collect_prediction_at(p_ts)` | Аналогично, но для исторического обучения. |
| `update_prediction_outcomes()` | Обновляет поля `actual_outcome`, `first_incident_time` и `incident_count` для прогнозов, у которых истёк горизонт. |
| `recalculate_prediction_risks(horizon)` | Пересчитывает предсказанные риски на основе текущей матрицы вероятностей (используется после переобучения). |
| `find_optimal_horizon(target, min, max, step)` | Подбирает горизонт, при котором доля переходов, за которыми следует инцидент, близка к целевому значению. |

### 3.4. Управление критическими состояниями

| Функция | Описание |
|---------|----------|
| `refresh_critical_states(p_start, p_end, min_transitions, interval_min, risk_threshold, dry_run, audit)` | Автоматически обновляет список критических состояний на основе эмпирического риска (вычисляемого через `compute_empirical_incident_risk`). Поддерживает режим `dry_run` и аудит. |
| `compute_empirical_incident_risk(start, end, min_transitions, interval_min)` | Вычисляет эмпирическую вероятность наступления инцидента в течение заданного интервала после каждого перехода в состояние. |
| `get_critical_states(only_with_transitions)` | Возвращает список аварийных состояний (с параметрами и временем последнего перехода). |
| `get_critical_state_ids(only_with_transitions)` | Упрощённая версия – только идентификаторы. |
| `update_last_incident_time()` | Триггерная функция, обновляющая `last_incident_time` в `markov_config` при аварийном переходе. |

### 3.5. Отчёты и метрики качества

| Функция | Описание |
|---------|----------|
| `mchain_quality_report(start, end, horizon)` | Формирует текстовый отчёт о качестве прогнозов: Brier, Log‑Loss, MAE, ECE, MCE, ROC‑AUC, калибровочная таблица, динамика из истории. |
| `mchain_reliability_report()` | Расширенный отчёт о достоверности прогнозов (объём данных, стабильность, покрытие, рейтинг 0‑5). |
| `mchain_incident_transitions_report(start, end)` | Анализ переходов в аварийные состояния: сырая статистика vs. взвешенная модель, динамика по интервалам. |
| `mchain_summary_report(start, end)` | Сводный отчёт, объединяющий достоверность, переходы в аварию, конфигурацию, текущее состояние и прогноз риска. |
| `mchain_health_check()` | Проверяет состояние модели и возвращает статус (OK/WARNING/CRITICAL) с кратким сообщением и описанием. |
| `mchain_state_transition_matrix_report(use_weighted, include_wait)` | Матрица переходов между макрогруппами состояний (3×3×3 или 3×3). |
| `report_stability_trend(lookback_days)` | Мониторинг стабильности вероятностей по 7‑дневным периодам. |
| `report_quality_sliding(window_days, step_days)` | Качество прогнозов в скользящем окне (из истории). |
| `report_daily_calibration(date)` | Детальная калибровочная кривая за указанный день. |
| `state_distribution(lookback_days)` | Распределение состояний и частота критических состояний. |
| `report_forgetting_effectiveness()` | Эффективность забывания – результаты оптимизации параметров. |
| `report_prediction_incident_summary(start, end)` | Сводный отчёт по прогнозам и инцидентам производительности. |
| `calculate_daily_quality_metrics(date)` | Расчёт суточных метрик и сохранение в историю (ECE, MCE). |
| `mchain_forecast_reliability()` | Оценивает достоверность прогнозов от 0 до 5 (объём, стабильность, покрытие). |

### 3.6. Служебные и вспомогательные функции

| Функция | Описание |
|---------|----------|
| `mchain_clean_transition_log(retention_days)` | Удаляет записи `transition_log` старше заданного срока (из конфигурации). |
| `mchain_clean_apply_forgetting_log(retention_days)` | Очищает журнал забывания. |
| `mchain_log_error(...)` | Записывает ошибку в `mchain_error_log`. |
| `format_timestamptz_to_minute(ts)` | Форматирует TIMESTAMPTZ до минут (для вывода в отчётах). |
| `adaptive_configure_markov_chain(end)` | Адаптивно настраивает параметры конфигурации на основе частоты инцидентов за период `transition_log_retention_days`. |
| `optimize_forgetting_params()` | Процедура эмпирического подбора параметров забывания (поиск по сетке с оценкой Brier) и обновления конфигурации. |
| `evaluate_forgetting_params(...)` | Оценивает качество для заданного набора параметров (используется в оптимизации). |

### 3.7. Историческое обучение

| Функция / Процедура | Описание |
|---------------------|----------|
| `fill_performance_history(start, end)` | Заполняет `performance_history` из `cluster_stat_median` за указанный период (вычисляет корреляцию и углы трендов). |
| `append_performance_history(start, end)` | Инкрементально добавляет/обновляет записи в `performance_history` (без TRUNCATE). |
| `mchain_train_step_at(ts)` | Шаг обучения для исторической минуты на основе данных из `performance_history`. |
| `mchain_log_transition_at(from, to, ts)` | Логирует переход с заданным временем (для исторического обучения). |
| `mchain_train_historical(end_time)` | Полное историческое обучение от минимальной даты в `cluster_stat_median` до `end_time` с логированием прогресса. |
| `mchain_train_historical_chunk(start, end)` | Обучение за непрерывный отрезок времени (для пакетной обработки, не управляет триггерами). |
| `mchain_initial_train_from_history(end, refresh_critical, ...)` | Первоначальное обучение с очисткой всех таблиц модели, имитацией реального времени и обновлением критических состояний. Поддерживает параметр `p_start` для задания начала. |

## 4. Функции профилирования нагрузки

Эти функции реализованы в отдельном файле `markov_chain_profile_functions.sql` и служат для построения и сравнения профилей производительности.

### 4.1. Расчёт и сохранение профилей

| Функция | Описание |
|---------|----------|
| `calculate_profile_metrics(start, end)` | Вычисляет набор профильных метрик для заданного окна: гистограмма состояний, средняя корреляция, доля критических, энтропия, углы трендов, количество уникальных состояний, средняя длина перехода, доля петель, самый частый переход. |
| `save_operational_profile()` | Сохраняет профиль за последние 60 минут (тип 'operational') и автоматически проверяет аномалии. |
| `save_daily_profile()` | Сохраняет профиль за последние 24 часа (тип 'daily'). |
| `save_weekly_profile()` | Сохраняет профиль за последние 7 дней (тип 'weekly'). |
| `save_baseline_profile()` | Сохраняет эталонный профиль на основе окна из `incident_free_window_current` (тип 'baseline'). |
| `save_current_profile(window_minutes)` | Сохраняет текущий профиль за указанное число минут (тип 'current'). |

### 4.2. Построение эталона и сравнение

| Функция | Описание |
|---------|----------|
| `build_baseline_profile(start, end, baseline_name, exclude_before, exclude_after, min_hours)` | Строит эталонный профиль для каждого часа и дня недели на основе исторических данных, исключая окна вокруг инцидентов. Заполняет таблицу `profile_baseline`. |
| `get_incident_free_window_before(ts, window_minutes, ...)` | Возвращает безынцидентное окно, заканчивающееся не позже заданного момента, с максимальным концом (использует самый поздний завершённый инцидент). |
| `find_incident_free_window(window_minutes, ...)` | Находит и сохраняет в `incident_free_window_current` безынцидентное окно заданной длины, максимально близкое к текущему моменту (на основе последнего завершённого инцидента). |
| `compare_profiles(window_minutes, ...)` | Сравнивает текущий профиль с эталонным, вычисляет JS-дивергенцию, определяет статус (NORMAL/WARNING/CRITICAL), вычисляет максимальный предсказанный риск и флаг предаварийного состояния, сохраняет результат в `profile_comparison_log`. |
| `histogram_divergence(h1, h2)` | Вычисляет JS-дивергенцию между двумя гистограммами состояний (JSON-формат). |

### 4.3. Детекция аномалий

| Функция | Описание |
|---------|----------|
| `detect_anomaly(profile_type, hour, dow, threshold)` | Для заданного типа профиля и временного слота вычисляет Z-оценки текущих метрик относительно эталона и возвращает список метрик, превысивших порог. |
| `get_deviation_report(profile_type, ts)` | Возвращает отчёт об отклонениях для последнего профиля указанного типа (сравнение с эталоном, severity). |
| `log_anomaly(...)` | Записывает обнаруженную аномалию в `anomaly_log`. |
| `check_and_log_anomalies(profile_type, threshold)` | Проверяет последний профиль на аномалии и логирует результат. |
| `check_anomalies_manual(profile_type, threshold)` | Ручной вызов проверки аномалий. |

### 4.4. Отчёты по профилям

| Функция | Описание |
|---------|----------|
| `generate_profile_summary_report()` | Краткий отчёт по текущим профилям (operational, daily, weekly) с основными метриками и аномалиями. |
| `generate_detailed_profile_report()` | Расширенный отчёт, включающий контекстные метрики производительности, связь с инцидентами, сравнение с предыдущим периодом и прогнозные метрики. |
| `compare_profile_windows(window1_start, window1_end, window2_start, window2_end)` | Сравнивает два произвольных окна (задаются строками) и возвращает детальный отчёт с изменениями. |
| `generate_profile_incident_analytics_report(start, end)` | Аналитический отчёт по связи сравнений профилей и инцидентов за период. |
| `generate_comprehensive_analytical_report(start, end)` | Сводный отчёт, объединяющий производительность, прогнозы и профили, с корреляциями и трендами. |
| `generate_analytical_report(start, end)` | Отчёт по заданному периоду, исключающий статус INCIDENT, с акцентом на качество прогнозов и связь с инцидентами. |
| `historical_fill_profile_comparison_log(start, end, window_minutes, step_minutes, overwrite)` | Процедура исторического заполнения `profile_comparison_log` для каждой минуты диапазона. |

### 4.5. Обслуживание

| Функция | Описание |
|---------|----------|
| `clean_profile_comparison_log()` | Удаляет записи из `profile_comparison_log` старше срока хранения (из `markov_config.profile_comparison_retention_days`). |
| `refresh_performance_history()` | Дополняет `performance_history` новыми данными из `cluster_stat_median` (инкрементально). |

## 5. Примечания по архитектуре

- **Модель** использует дискретное пространство состояний размером 189 (21 градация корреляции × 3 тренда OS × 3 тренда WAIT).
- **Обучение** происходит пошагово (каждую минуту) и поддерживает историческое обучение (воспроизведение прошлых данных).
- **Забывание** может быть фиксированным или адаптивным (alpha зависит от времени, прошедшего с последнего инцидента). Коэффициент стабильности корректирует alpha при нестабильных вероятностях.
- **Прогнозирование** использует итеративное умножение вектора распределения на матрицу переходов, обнуляя вероятности критических состояний на каждом шаге для учёта только первого попадания.
- **Профилирование** позволяет выявлять аномалии на основе статистического сравнения с эталоном (Z-оценки, JS-дивергенция) и связывать их с риском инцидентов.
- Все ключевые процессы снабжены журналами ошибок, аудитом и поддерживают очистку старых данных через cron-задачи.
