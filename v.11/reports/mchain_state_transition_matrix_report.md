## Описание логики работы и интерпретация отчёта `mchain_state_transition_matrix_report` (актуальная версия)

Функция `mchain_state_transition_matrix_report` строит **агрегированную матрицу переходов** между укрупнёнными группами состояний цепи Маркова. Она позволяет быстро оценить, как система перемещается между макросостояниями, и выявить доминирующие траектории, не углубляясь в детали 189 отдельных состояний.

---

### 1. Назначение

Отчёт предназначен для:
- визуализации общей динамики системы на уровне групп;
- выявления устойчивых переходов между типами состояний;
- оценки того, в какие группы система чаще всего переходит из текущего состояния (блок «Переходы из текущего состояния» временно отключён в версии 11.4, но логика описана);
- поддержки принятия решений при анализе рисков и настройке параметров модели.

---

### 2. Параметры вызова (текущая реализация)

```sql
mchain_state_transition_matrix_report(
    p_use_weighted      BOOLEAN DEFAULT FALSE,
    p_include_wait_trend BOOLEAN DEFAULT TRUE   -- внимание: по умолчанию TRUE!
)
```

| Параметр | Значение | Описание |
|----------|----------|----------|
| `p_use_weighted` | `FALSE` (по умолч.) | Вероятность перехода между группами вычисляется как **простое среднее** вероятностей всех индивидуальных переходов, входящих в эти группы. |
| | `TRUE` | Вероятность вычисляется как **взвешенное среднее** с весами, равными частотам исходных состояний (`frequency` из `markov_frequencies`). Это даёт больший вклад более часто посещаемым состояниям. |
| `p_include_wait_trend` | `TRUE` (по умолч.) | Группировка выполняется по трём признакам: **знак корреляции** (Neg / Zero / Pos), **тренд операционной скорости** (down / stable / up) и **тренд времени ожидания** (down / stable / up). Итого **3 × 3 × 3 = 27 групп**. |
| | `FALSE` | Группировка только по двум признакам: знак корреляции и тренд OS – **9 групп**. |

**Важно:** В примере вызова (`select mchain_state_transition_matrix_report();`) используются параметры по умолчанию, поэтому отчёт построен для 27 групп с простым усреднением.

---

### 3. Логика построения матрицы

1. **Определение групп**  
   Каждому из 189 состояний ставится в соответствие метка группы на основе его параметров (`correlation`, `os_trend`, `wait_trend`).  
   Например, для `p_include_wait_trend = TRUE`:
   - `correlation < 0` → `Neg`  
   - `correlation = 0` → `Zero`  
   - `correlation > 0` → `Pos`  
   - `os_trend = -1` → `down`, `0` → `stable`, `1` → `up`  
   - `wait_trend = -1` → `down`, `0` → `stable`, `1` → `up`  
   Метка формируется как `Neg_down_down`, `Pos_stable_up` и т.д.

2. **Агрегация вероятностей**  
   Из таблицы `markov_probabilities` берутся все условные вероятности `P(to_state | from_state)`. Для каждой пары групп `(G_from, G_to)` вычисляется агрегированная вероятность:

4. **Формирование матрицы**  
   Строки и столбцы соответствуют группам. На пересечении – агрегированная вероятность перехода. Если для пары групп нет ни одного перехода, ставится `---`.

5. **Блок «Переходы из текущего состояния»** (в текущей версии закомментирован, но логически он должен выводить распределение вероятностей из текущего состояния по группам). В примере вывода этот блок отсутствует, поэтому мы не будем его интерпретировать.

### 4. Интерпретация результатов (на основе примера)

В приведённом примере отчёт построен для 27 групп, но в выводе отображаются только те группы, для которых существуют ненулевые переходы (или группы, которые встречаются в данных). Всего в таблице 14 групп (из 27 возможных). Это означает, что остальные 13 групп либо не имеют состояний, либо из них/в них не было переходов (вероятности равны нулю).

#### 4.1. Заголовок отчёта
- **Группировка** – 27 групп (знак корреляции + тренд OS + тренд wait).  
- **Способ усреднения** – простое среднее.

#### 4.2. Матрица переходов
- **Строки** – исходные группы (откуда).  
- **Столбцы** – целевые группы (куда).  
- **Значение** – средняя вероятность перехода из строки в столбец.  
  **Важно:** вероятности **не нормированы по строке** (сумма в строке может быть ≠ 1), потому что это средние по множеству состояний внутри группы. Они показывают **среднюю силу связи** между группами, а не распределение вероятностей для конкретного состояния.  
- **`---`** – отсутствие переходов между данными группами (вероятность = 0 или слишком мала, чтобы быть учтённой).

#### 4.3. Разбор конкретных значений (из примера)

Рассмотрим строку `-downdown` (отрицательная корреляция, тренд OS вниз, тренд wait вниз):
- Переход в `-downdown`: 0.658  
- Переход в `-updown`: 1.000  
- Переход в `0downdown`: 0.027  
Остальные – `---`.

Это означает, что в среднем из состояний группы `-downdown` вероятность перейти в группу `-updown` составляет 1.0 (т.е. все состояния этой группы, для которых есть переходы, ведут исключительно в группу `-updown`). Однако обратите внимание: сумма по строке (0.658 + 1.000 + 0.027) > 1, что возможно, потому что это средние по разным состояниям, а не распределение для одного состояния.

Другой пример: строка `-downup` (отрицательная корреляция, тренд OS вниз, тренд wait вверх):
- Переход в `-downup`: 0.326  
- Переход в `-upup`: 0.001  
- Переход в `0downup`: 0.475  
Сумма ~0.802, остальные – `---`. Это говорит о том, что состояния этой группы имеют сильную связь с группами `-downup` и `0downup`, а также слабую связь с `-upup`.

Строка `+downdown` (положительная корреляция, тренд OS вниз, тренд wait вниз):
- Переход в `+downdown`: 0.308  
- Переход в `+downup`: 0.151  
- Переход в `+updown`: 0.012  
- Переход в `0downdown`: 0.605  
- Переход в `0downstable`: 0.000 (фактически 0, но отображается как 0.000)  
Сумма ~1.076. Здесь видно, что основная масса переходов направлена в группу `0downdown` (0.605), а также значительная доля остаётся в своей группе (0.308).

Строка `0upup`:
- Переход в `+upup`: 0.333  
- Переход в `0upup`: 0.667  
Это означает, что состояния с нулевой корреляцией, трендом OS вверх и трендом wait вверх с вероятностью 2/3 остаются в той же группе, а с вероятностью 1/3 переходят в группу `+upup`.

#### 4.4. Почему некоторые группы отсутствуют?
В данных могут отсутствовать состояния с определёнными комбинациями параметров (например, `Zero_stable_down`), либо они никогда не встречались в переходах. Функция строит матрицу только по фактическим переходам, поэтому пустые группы не выводятся. Это позволяет сфокусироваться на реально существующих связях.

---

### 5. Практическое применение

- **Мониторинг стабильности** – если матрица сильно меняется со временем, это сигнал о смене режима работы системы.
- **Выявление «ловушек»** – группы с высокими значениями на диагонали (остаться в той же группе) могут указывать на устойчивые состояния.
- **Оценка риска** – если текущее состояние (если бы блок был активен) имеет высокую вероятность перехода в группу с отрицательной корреляцией и падением OS, это может быть предвестником аварийных ситуаций.
- **Настройка параметров** – при включении взвешенного усреднения можно учесть частоту посещения состояний, что даёт более репрезентативную картину для часто встречающихся сценариев.

---

### 6. Особенности текущей версии (11.4)

- Блок «Переходы из текущего состояния» закомментирован – в выводе его нет. Если потребуется, его можно раскомментировать в коде функции.
- Параметр `p_include_wait_trend` по умолчанию `TRUE`, поэтому матрица имеет размерность 27×27 (но отображаются только группы с данными).
- Усреднение по умолчанию – простое среднее; взвешенное усреднение включается параметром `p_use_weighted = TRUE`.

---

### 7. Примечания

- Если таблица `markov_probabilities` пуста (модель не обучена), функция вернёт сообщение об ошибке.
- Значения вероятностей в матрице являются **средними**, а не **нормированными**, поэтому не следует интерпретировать их как вероятности перехода из конкретного состояния – для этого используйте прямые запросы к `markov_probabilities` или включите блок текущего состояния.
- Символ `---` означает отсутствие переходов (вероятность равна 0).

---

### 8. Заключение

`mchain_state_transition_matrix_report` – мощный инструмент для быстрого анализа макроскопического поведения цепи Маркова. Он позволяет выявить доминирующие траектории, оценить связность групп и понять, в каком направлении движется система в среднем. Правильная интерпретация требует учёта способа усреднения и того факта, что агрегированные вероятности не являются классическими условными вероятностями для отдельных состояний.
