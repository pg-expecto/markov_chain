# Сводный отчёт по состоянию цепи Маркова (mchain_summary_report)

Данный документ описывает структуру и интерпретацию сводного отчёта, который формируется функцией `mchain_summary_report()` в модуле цепи Маркова. Отчёт предназначен для оперативного мониторинга состояния модели прогнозирования риска и включает информацию о конфигурации, текущем состоянии системы, достоверности прогнозов и практических рекомендациях.

Ниже представлен пример вывода (файл `2.txt`) с детальным разбором каждого раздела.

---

## Детальное описание разделов

### 1. Заголовок и период
- **«СВОДНЫЙ ОТЧЁТ ПО СОСТОЯНИЮ ЦЕПИ МАРКОВА»** – название отчёта.
- **«Период анализа переходов»** – временной интервал, за который анализируются переходы для оценки частот и стабильности (по умолчанию последние 7 дней, может быть задан при вызове функции).
- **«Дата формирования отчёта»** – момент генерации отчёта (с точностью до минуты).

---

### 2. Раздел 1. КОНФИГУРАЦИЯ МОДЕЛИ
В этом блоке отображаются текущие параметры из таблицы `markov_config`, влияющие на обучение и забывание:

| Параметр | Описание |
|----------|----------|
| **Адаптивное забывание** | Включено ли глобальное забывание (`adaptive_forgetting_enabled`). Если **ВЫКЛ**, забывание не применяется. |
| **Динамический alpha** | Используется ли адаптивный коэффициент забывания (`use_adaptive_alpha`). При **ВКЛ** alpha вычисляется на основе времени с последнего инцидента. |
| **base_alpha** | Базовый коэффициент забывания, используемый при частых инцидентах (если динамический режим включён). |
| **min_alpha** | Минимально возможный alpha (при очень редких инцидентах). |
| **half_life (дни)** | Период полураспада влияния инцидента на alpha (чем больше, тем медленнее уменьшается alpha). |
| **Интервал забывания (минут)** | Частота вызова планового забывания (`interval_minute`). |
| **Порог переходов для забывания** | Минимальное общее число переходов, необходимое для начала применения забывания (`min_transitions_for_forgetting`). |
| **Глубина хранения transition_log (дней)** | Срок хранения журнала переходов для анализа (используется функцией очистки). |
| **Горизонт прогноза (минут)** | Основной горизонт, на который рассчитывается риск (используется в прогнозах и отчётах). |
| **Последнее забывание** | Время последнего успешного применения забывания. |
| **Последний инцидент** | Время последнего перехода в аварийное состояние (обновляется автоматически триггером). |

**Назначение:** позволяет быстро оценить, как настроена модель и когда происходили ключевые события.

---

### 3. Раздел 2. ТЕКУЩЕЕ СОСТОЯНИЕ СИСТЕМЫ И ПРОГНОЗ РИСКА
- **State ID** – числовой идентификатор текущего состояния системы (из 189 возможных).  
- **Параметры** – расшифровка state ID в терминах:  
  - `correlation` – коэффициент корреляции (от –1 до +1 с шагом 0.1);  
  - `os_trend` – тренд операционной скорости (–1 – снижение, 0 – стабильно, +1 – рост);  
  - `wait_trend` – тренд времени ожидания (–1 – снижение, 0 – стабильно, +1 – рост).  
- **Прогноз риска на ХХ мин** – вероятность хотя бы одного попадания в аварийное состояние в течение заданного горизонта (вычисляется с помощью `mchain_predict_risk_k_v2` на основе динамического списка `critical_states`). Значение от 0 до 1.

**Назначение:** показывает текущее состояние системы и количественную оценку риска на ближайшие минуты.

---

### 4. Раздел 3. ДОСТОВЕРНОСТЬ ПРОГНОЗОВ
Этот раздел представляет собой вложенный отчёт `mchain_reliability_report()`, который оценивает, насколько можно доверять прогнозам модели. Он состоит из трёх подразделов.

#### 3.1. ОБЩИЙ РЕЙТИНГ ДОСТОВЕРНОСТИ (0–5)
- Рейтинг вычисляется на основе трёх критериев: объёма данных, стабильности вероятностей и покрытия частых состояний.
- **Интерпретация** (для каждого значения):
  - **0** – модель не обучена (менее 100 переходов).
  - **1** – крайне низкая достоверность (мало данных или сильная нестабильность).
  - **2** – низкая достоверность.
  - **3** – минимально допустимый уровень (можно использовать с осторожностью).
  - **4** – хорошая достоверность.
  - **5** – отличная достоверность, прогнозам можно доверять полностью.

#### 3.2. ДЕТАЛИЗАЦИЯ ПО МЕТРИКАМ
- **Общее число переходов** (`total_transitions`) – количество записей в `transition_log`. Сравнивается с порогом `min_transitions_for_forgetting` (обычно 5000). Статус: *ДОСТАТОЧНО* / *НЕДОСТАТОЧНО*.
- **Максимальное изменение вероятностей за две недели** (`max_prob_change`) – максимальное абсолютное изменение вероятности перехода между двумя недельными интервалами. Порог стабильности – 0.05. Статус: *СТАБИЛЬНО* / *НЕСТАБИЛЬНО*. Высокое изменение указывает на дрейф модели, что снижает точность прогнозов.
- **Покрытие частых состояний** (`coverage_pct`) – доля состояний с частотой >1%, для которых накоплено не менее 50 переходов. Рекомендуемый порог – 90%. Статус: *ХОРОШЕЕ* / *НИЗКОЕ*. Низкое покрытие означает, что некоторые часто встречающиеся состояния имеют недостаточную статистику для надёжной оценки вероятностей.

#### 3.3. РЕКОМЕНДАЦИИ
На основе общего рейтинга формируются практические советы:
- Для рейтинга ≤2: не использовать прогнозы для принятия решений; накопить больше данных; проверить поступление метрик.
- Для рейтинга 3: использовать с осторожностью; периодически проверять стабильность и покрытие.
- Для рейтинга 4: прогнозы достаточно надёжны; для достижения 5 рекомендуется улучшить стабильность или покрытие.
- Для рейтинга 5: модель полностью готова; поддерживать актуальность через забывание.

---

### 5. Заключительная часть
- Повторяется **дата формирования отчёта** (для удобства).

## Дополнительная информация

### Как интерпретировать рейтинг достоверности
Рейтинг строится по следующему алгоритму (функция `mchain_forecast_reliability`):

1. **Базовая оценка по объёму данных** (0–3 балла):
   - < 100 переходов → 0
   - < 500 → 1
   - < 5000 → 2
   - ≥ 5000 → 3

2. **Если данных ≥ 5000**, учитываются:
   - Стабильность (`max_prob_change`):
     - < 0.02 → +2 балла
     - < 0.05 → +1 балл
     - > 0.5 → -2 балла
     - > 0.2 → -1 балл
   - Покрытие частых состояний:
     - если `max_prob_change < 0.2` и `coverage_pct ≥ 90` → +1 балл

3. Итоговый рейтинг ограничивается 5.

Таким образом, рейтинг 5 достигается только при большом объёме данных, высокой стабильности и хорошем покрытии.

### Важные замечания
- Отчёт генерируется на основе текущих данных и конфигурации. Если модель только начала обучение, многие метрики могут быть недоступны (отображаются как «недостаточно данных»).
- Список аварийных состояний (`critical_states`) динамический и может обновляться функцией `refresh_critical_states`. В прогнозе риска используются именно эти состояния.
- Горизонт прогноза берётся из `markov_config.forecast_horizon_minutes` (по умолчанию 30 минут).

---

## Использование
Вызов отчёта в SQL:
```sql
SELECT mchain_summary_report();  -- за последние 7 дней
SELECT mchain_summary_report('2026-06-01', '2026-06-20'); -- за произвольный период
```

Результат – текстовая строка, которую можно вывести в консоль или сохранить в лог.

---

## Заключение
Сводный отчёт является основным инструментом для быстрой оценки состояния цепи Маркова. Он объединяет в себе конфигурацию, текущий риск, достоверность прогнозов и чёткие рекомендации, что позволяет оперативно принимать решения о необходимости корректировки модели или её параметров.
