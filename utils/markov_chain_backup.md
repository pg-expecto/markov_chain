# Резервное копирование и восстановление цепи Маркова

Данный инструментарий обеспечивает **выборочное резервное копирование и восстановление** всех таблиц, относящихся к цепи Маркова, с возможностью **восстановления пропущенных переходов** на основе исторических метрик производительности. Это позволяет сохранить непрерывность модели даже в случае длительных экспериментов или перерывов в сборе данных, **не затрагивая другие объекты базы данных**.

---

## 📌 Назначение

- **Выборочный бекап** – создание дампа только таблиц цепи Маркова (без функций, представлений и прочих объектов) с сохранением момента времени.
- **Восстановление** – восстановление только таблиц цепи из бекапа с последующей **автоматической реконструкцией** переходов, произошедших в промежутке между временем бекапа и моментом восстановления, на основе данных из таблиц производительности (`cluster_stat_median`, `performance_incident`).
- **Проверка** – после восстановления выполняются все необходимые шаги для приведения цепи в рабочее состояние: обновление текущего состояния, пересчёт критических состояний, вероятностей и прогнозов.

---

## 🛠️ Требования

- **PostgreSQL** 12 или выше.
- Утилиты командной строки: `pg_dump`, `pg_restore`, `psql`.
- Переменная окружения `PGPASSWORD` (или настроенный `.pgpass`) для аутентификации.
- База данных с именем `expecto_db` и пользователем `expecto_user` (параметры жёстко зафиксированы в скрипте).
- Наличие таблиц цепи Маркова и таблиц производительности (`cluster_stat_median`, `performance_incident`).

## 🚀 Использование

### Создание бекапа

```bash
./markov_chain_backup.sh backup
```

- Будет создан дамп только таблиц цепи Маркова в `/tmp/markov_chain_tables_YYYYMMDD_HHMMSS.dump`.
- Время бекапа автоматически сохранится в таблицу `backup_metadata`.

### Восстановление

```bash
./markov_chain_backup.sh restore
```

Скрипт:
1. Найдёт самый свежий файл бекапа в `/tmp`.
2. Запросит подтверждение.
3. Выполнит восстановление таблиц из бекапа (с очисткой – `pg_restore --clean`).
4. Последовательно выполнит:
   - `mchain_train_step()` – обновит текущее состояние.
   - `fill_missing_transitions()` – восстановит пропущенные переходы (если есть время бекапа).
   - `refresh_critical_states()` – пересчитает критические состояния за последние 14 дней.
   - `update_markov_probabilities()` и `rebuild_markov_absorbing()` – перестроит матрицы.
   - `mchain_predict_risk_current_horizon()` – проверит прогноз.

Все шаги выводят подробный лог в консоль.

## 📋 Таблицы, входящие в бекап

Скрипт сохраняет и восстанавливает **только** следующие таблицы (все остальные объекты базы не затрагиваются):

| Имя таблицы | Описание |
|-------------|----------|
| `markov_config` | Конфигурация цепи |
| `mchain_error_log` | Журнал ошибок |
| `markov_frequencies` | Накопленные частоты переходов |
| `transition_log` | Журнал переходов |
| `markov_probabilities` | Матрица вероятностей |
| `markov_absorbing` | Поглощающая матрица |
| `state_descriptions` | Справочник состояний |
| `markov_chain` | Текущее состояние |
| `apply_forgetting_log` | Журнал забывания |
| `prediction_log` | Журнал прогнозов |
| `mchain_quality_metrics_history` | Агрегированные метрики качества |
| `mchain_quality_errors` | Ошибки прогнозов |
| `critical_states` | Критические состояния |
| `forgetting_optimization_log` | Журнал экспериментов по забыванию |
| `backup_metadata` | Время бекапа (вспомогательная) |

## 🔧 Детали реализации

### Таблица `backup_metadata`

| Колонка       | Тип           | Описание                      |
|---------------|---------------|-------------------------------|
| `id`          | SERIAL        | Первичный ключ                |
| `backup_time` | TIMESTAMPTZ   | Время создания бекапа         |
| `created_at`  | TIMESTAMPTZ   | Время записи (по умолчанию now) |

Используется для хранения времени бекапа, чтобы при восстановлении знать, с какого момента восстанавливать переходы.

### Функция `get_state_at_time`

- Принимает `TIMESTAMPTZ`.
- Использует окно в **1 час** для вычисления корреляции между `curr_op_speed` и `curr_waitings` и трендов (регрессия методом наименьших квадратов).
- Возвращает `state_id`, `correlation`, `os_trend`, `wait_trend`.
- Работает без временных таблиц (использует CTE), что позволяет объявить её как `STABLE` и избежать ошибок DDL.

### Функция `fill_missing_transitions`

- Принимает `p_backup_time` и `p_restore_time` (по умолчанию `now()`).
- Перебирает каждую минуту в диапазоне (шаг – 1 минута, как в реальном обучении).
- Для каждой минуты вычисляет состояние через `get_state_at_time`.
- При изменении состояния вставляет переход в `transition_log` и обновляет `markov_frequencies`.
- В конце обновляет `markov_chain` на последнее состояние, обновляет `last_incident_time` из `performance_incident`, пересчитывает вероятности и поглощающую матрицу.
- Возвращает текстовый отчёт о количестве вставленных переходов и факте обновления инцидентов.

### Скрипт `markov_chain_backup.sh`

- Жёстко заданы параметры подключения: `expecto_db`, `expecto_user`, `localhost`, `5432`.
- Использует переменную `PGPASSWORD` для аутентификации.
- В действии `backup`:
  - Проверяет/создаёт таблицу `backup_metadata`.
  - Создаёт выборочный дамп (только перечисленные таблицы) и записывает время.
- В действии `restore`:
  - Проверяет наличие вспомогательных функций (`get_state_at_time`, `fill_missing_transitions`).
  - Восстанавливает таблицы из дампа с очисткой.
  - Выполняет пост-восстановительные шаги.

## ⚠️ Ограничения и важные замечания

- **Точность восстановления** зависит от качества и полноты данных в `cluster_stat_median`. Если в пропущенном периоде нет записей за какие-то минуты, состояние будет вычислено по доступным данным, что может привести к неточностям.
- **Забывание** за пропущенный период не воспроизводится. Это допустимо, так как после восстановления частоты будут чуть выше реальных, но следующий плановый вызов забывания скорректирует их.
- **Длительные пропуски** – для периода более нескольких дней цикл по минутам может быть медленным. В таких случаях рекомендуется оптимизировать функцию `fill_missing_transitions` (например, использовать пакетную вставку) или сократить период восстановления.
- **Выборочное восстановление** – скрипт восстанавливает **только** таблицы, перечисленные выше. Функции, представления, последовательности и другие объекты **не затрагиваются**. Это безопасно, но требует, чтобы функции `get_state_at_time` и `fill_missing_transitions` существовали в базе отдельно.
- **Внешние зависимости** – скрипт предполагает, что таблицы производительности (`cluster_stat_median`, `performance_incident`) существуют и содержат данные за нужный период. Их структура не входит в бекап, и они не восстанавливаются скриптом.
