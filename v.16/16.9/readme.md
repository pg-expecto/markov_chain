# README: Цепь Маркова для прогнозирования производительности PostgreSQL (v.16.9)

## Обзор

Репозиторий **pg-expecto/markov_chain** содержит реализацию цепи Маркова для анализа и прогнозирования производительности СУБД PostgreSQL. Версия `16.9` включает модули обучения цепи, расчёта вероятностей переходов, прогнозирования рисков, профилирования нагрузки и обнаружения аномалий.

Система работает с историческими метриками производительности (таблица `cluster_stat_median`) и инцидентами (таблица `performance_incident`), позволяя строить адаптивные модели, оценивать вероятность деградации и формировать отчёты о стабильности кластера.

## Ключевые возможности

- **Обучение цепи Маркова** на исторических данных с поддержкой пошагового обновления.
- **Адаптивное забывание** устаревших переходов — по расписанию или в зависимости от накопленной статистики.
- **Прогнозирование рисков** на заданном горизонте с оценкой достоверности прогноза.
- **Профилирование нагрузки**: оперативные, суточные и недельные профили метрик.
- **Обнаружение аномалий и отклонений** в профилях нагрузки.
- **Динамическое определение критических состояний** на основе зафиксированных инцидентов.
- **Журналирование** переходов, ошибок, применённого забывания и качества прогнозов.
- **Гибкая конфигурация режима прогнозирования** через таблицу `incident_forecast_config`.

## Модель данных

Основные сущности системы:

| Компонент | Назначение |
|-----------|------------|
| `cluster_stat_median` | Исторические метрики производительности: время, скорость операций, ожидания |
| `performance_incident` | Зафиксированные инциденты с приоритетом и интервалами |
| `configuration` | Управляющий флаг `is_markov_chain_enabled` |
| `incident_forecast_config` | Параметры режима прогнозирования и весов сигналов |
| Матрицы вероятностей и поглощения | Внутреннее состояние цепи Маркова |
| Журналы обучения и прогнозов | Диагностика, история переходов и качество модели |
| Профильные таблицы | Агрегированные оперативные, суточные и недельные профили нагрузки |

## Ключевые функции

### Обучение цепи

- **`mchain_train_step()`** — выполняет один шаг обучения цепи Маркова. Обычно вызывается приложением с заданной периодичностью (например, каждую минуту) при включённом флаге `is_markov_chain_enabled`.
- **`mchain_train_historical(end_time TIMESTAMPTZ)`** — выполняет полное историческое обучение до указанного момента времени. Используется для первоначального заполнения модели или переобучения на ретроспективных данных.

### Прогнозирование

- **`collect_prediction()`** — формирует прогноз риска на заданный горизонт. Учитывает вероятности переходов, критические состояния и параметры из `incident_forecast_config`.
- Режим прогнозирования поддерживает взвешивание сигналов: например, `signal_mode = 'WEIGHTED'`, `weight_js` и `weight_risk`. Это позволяет комбинировать статистический сигнал и оценку риска.

### Профилирование нагрузки

- **`calculate_profile_metrics(...)`** — рассчитывает профильные метрики для выбранного временного окна: оперативные, суточные и недельные агрегаты.
- **`detect_anomaly(...)`** — выполняет обнаружение аномалий в профиле нагрузки. Результаты могут использоваться для раннего предупреждения деградации.

### Забывание и адаптация

- Механизм забывания снижает влияние устаревших данных на матрицу переходов.
- Поддерживается забывание по расписанию и адаптивное забывание с учётом накопленной статистики.
- Применённые операции забывания фиксируются в журналах для последующего анализа.

### Диагностика и качество

- Журналы содержат историю переходов, ошибки обучения, применённое забывание и оценки качества прогнозов.
- Вспомогательные функции в `performance_metrics_for_markov_chain.sql` предоставляют текущие метрики корреляции и трендов.

## Конфигурация прогнозирования

Параметры отчёта по прогнозированию задаются в таблице `incident_forecast_config`. Пример настройки:

```sql
UPDATE incident_forecast_config
SET signal_mode = 'WEIGHTED',
    weight_js = 0.9,
    weight_risk = 0.1,
    extended_report = TRUE;
```

Управление вызовом обучения из приложения осуществляется через флаг:

```sql
UPDATE configuration SET is_markov_chain_enabled = TRUE;
```

Если приложение не должно вызывать `mchain_train_step()`, флаг устанавливается в `FALSE`.
