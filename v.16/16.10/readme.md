## Обзор

Репозиторий **pg-expecto/markov_chain** содержит реализацию цепи Маркова для анализа и прогнозирования производительности СУБД PostgreSQL. Версия `16.10` (внутренняя версия `v3.1.1`) развивает функциональность версии `16.9`, добавляя расширенную отчётность по покрытию инцидентов, диагностику качества сигналов и новые параметры конфигурации.

Система работает с историческими метриками производительности (таблица `cluster_stat_median`) и инцидентами (таблица `performance_incident`), позволяя строить адаптивные модели, оценивать вероятность деградации и формировать детализированные отчёты о стабильности кластера с учётом времени упреждения (lead time).

## Ключевые возможности

- **Обучение цепи Маркова** на исторических данных с поддержкой пошагового обновления.
- **Адаптивное забывание** устаревших переходов — по расписанию или в зависимости от накопленной статистики.
- **Прогнозирование рисков** на заданном горизонте с оценкой достоверности прогноза.
- **Профилирование нагрузки**: оперативные, суточные и недельные профили метрик.
- **Обнаружение аномалий и отклонений** в профилях нагрузки.
- **Динамическое определение критических состояний** на основе зафиксированных инцидентов.
- **Расширенная отчётность по покрытию инцидентов** с разделением на «предсказано заранее» (lead ≥ порога) и «сигнал активен, но не предсказал» (lead < порога).
- **Диагностика качества сигналов** через функцию `diagnose_incident_coverage`, включая episode-based coverage и серийные фильтры.
- **Гибкая конфигурация режима прогнозирования** через таблицу `incident_forecast_config`, включая порог lead time и порог предупреждения о покрытии.
- **Журналирование** переходов, ошибок, применённого забывания и качества прогнозов.

## Модель данных

Основные сущности системы:

| Компонент | Назначение |
|-----------|------------|
| `cluster_stat_median` | Исторические метрики производительности: время, скорость операций, ожидания |
| `performance_incident` | Зафиксированные инциденты с приоритетом и интервалами |
| `configuration` | Управляющий флаг `is_markov_chain_enabled` |
| `incident_forecast_config` | Параметры режима прогнозирования, весов сигналов, а также `coverage_lead_threshold_min`, `series_filter_enabled`, `sicpp_coverage_warn_threshold_pct` |
| Матрицы вероятностей и поглощения | Внутреннее состояние цепи Маркова |
| Журналы обучения и прогнозов | Диагностика, история переходов и качество модели |
| Профильные таблицы | Агрегированные оперативные, суточные и недельные профили нагрузки |
| `sicpp_coverage_alerts` | Алерты о критических инцидентах (P3) без сигнала SICPP |

## Ключевые функции

### Обучение цепи

- **`mchain_train_step()`** — выполняет один шаг обучения цепи Маркова. Обычно вызывается приложением с заданной периодичностью (например, каждую минуту) при включённом флаге `is_markov_chain_enabled`.
- **`mchain_train_historical(end_time TIMESTAMPTZ)`** — выполняет полное историческое обучение до указанного момента времени. Используется для первоначального заполнения модели или переобучения на ретроспективных данных.

### Прогнозирование и отчётность

- **`collect_prediction()`** — формирует прогноз риска на заданный горизонт. Учитывает вероятности переходов, критические состояния и параметры из `incident_forecast_config`.
- **`generate_incident_forecast_report_v2()`** — **основная отчётная функция** (v3.1.1). Формирует детализированный отчёт, включающий:
  - раздел «ПОКРЫТИЕ С УЧЁТОМ LEAD TIME» (количество инцидентов с `lead >= coverage_lead_threshold_min` и `lead < порога`);
  - раздел «ПОКРЫТИЕ ПО ПРИОРИТЕТАМ»;
  - раздел «ТОЧНОСТЬ СИГНАЛА (PRECISION эпизодов)»;
  - раздел «РАСПРЕДЕЛЕНИЕ LEAD TIME»;
  - раздел «КРИТИЧЕСКИЕ АЛЕРТЫ (P3 без сигнала)».
- **`diagnose_incident_coverage()`** — диагностическая функция (v3.0.0+), переработанная для поддержки `priority_filter`, `status_filter`, `series_filter`, episode-based coverage и взвешенной оценки (WEIGHTED score).
- Устаревшие функции `generate_incident_forecast_report` (v1) и `report_incidents_vs_sicpp` помечены как deprecated и заменены заглушками с предупреждением.

### Профилирование нагрузки

- **`calculate_profile_metrics(...)`** — рассчитывает профильные метрики для выбранного временного окна: оперативные, суточные и недельные агрегаты.
- **`detect_anomaly(...)`** — выполняет обнаружение аномалий в профиле нагрузки. Результаты могут использоваться для раннего предупреждения деградации.

### Забывание и адаптация

- Механизм забывания снижает влияние устаревших данных на матрицу переходов.
- Поддерживается забывание по расписанию и адаптивное забывание с учётом накопленной статистики.
- Применённые операции забывания фиксируются в журналах для последующего анализа.

### Диагностика и качество

- Журналы содержат историю переходов, ошибки обучения, применённое забывание и оценки качества прогнозов.
- Вспомогательные функции в `performance_metrics_for_markov_chain.sql` предоставляют текущие метрики корреляции и трендов.
- В версии 16.10 (v3.1.1) уточнены легенды отчётов и добавлены комментарии к функциям с ожидаемыми значениями метрик (например, «покрытие с lead ≥ 60 мин» — 88% на тестовых данных).

## Конфигурация прогнозирования

Параметры отчёта по прогнозированию задаются в таблице `incident_forecast_config`. Пример настройки для версии 16.10:

```sql
UPDATE incident_forecast_config
SET signal_mode = 'WEIGHTED',
    weight_js = 0.9,
    weight_risk = 0.1,
    extended_report = TRUE,
    coverage_lead_threshold_min = 60,          -- новый параметр (v3.1.0+)
    series_filter_enabled = TRUE,              -- новый параметр (v3.0.0+)
    sicpp_coverage_warn_threshold_pct = 10.0;  -- новый параметр (v3.0.0+)
```

Управление вызовом обучения из приложения осуществляется через флаг:

```sql
UPDATE configuration SET is_markov_chain_enabled = TRUE;
```

Если приложение не должно вызывать `mchain_train_step()`, флаг устанавливается в `FALSE`.

## Результаты тестирования (v3.1.1)

Согласно `CHANGELOG.md`, на тестовых данных (test5) достигнуты следующие показатели:
- Покрытие инцидентов: **25/25 (100%)** (episode-based coverage).
- Покрытие с lead ≥ 60 мин: **22/25 (88%)** — инциденты предсказаны заранее.
- При пороге 120 мин: **16/25 (64%)** — предсказано заранее.
- Precision эпизодов: **37.5%** (18 TP / 30 FP из 48 эпизодов).
- ROC-AUC: **0.9568**, Brier: **0.0652** (при горизонте 120 мин).
